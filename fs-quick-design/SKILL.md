# 快速技术方案生成器（fs-quick-design）

> **首次使用先看这三条**（换机器 / 换人时最容易卡住的地方）：
> 1. **Python**：脚本 `scripts/gen_ui_svg.py` **纯标准库、零依赖**，任意 Python 3 均可。
>    Windows 用 `py -3`（官方启动器；直接写 `python` 可能命中 Store 占位 exe）；
>    macOS / Linux 用 `python3`。
> 2. **可选依赖**：读 `.docx` 输入需要 `tencent-local-office-edit`（见 §4.1）；
>    **没有也能用**——`.md` / 口述输入不受影响，图生成全流程也不受影响。
> 3. **本 skill 自包含**：`references/` 与 `examples/` 都在包内，用相对路径引用。
>    文末提到的 `fs-doc-generator` / `fs-doc-renderer` 是**同门兄弟 skill**，
>    只作"该走哪条路"的指路，**缺失不影响本 skill 单独使用**。

## 一、核心主张：第一轮只出两张框架图

**拿到需求，R1 交付两张框架图 + 界面图。**

理由：顾问最怕的不是"方案不够完美"，是**"你理解错了我的业务，却已经写了一堆设计"**。
两张框架图是**最便宜的对齐器**——顾问扫一眼就知道你把业务想对没有；
万一想错了，改的只是一张图，不是一份文档。

> **不要在 R1 把所有东西做完。** 顾问一定会提想法，
> 一次做全 = 一半白做，而且慢。**先对齐业务，再谈细节。**

**本 skill 明确不产出**：伪代码（v3.0.0 起移除）· 需求澄清 16 项 · 复用检索 · 需求拷打 ·
fresh eyes 评审 · 客户 FS 投影 · 正式 Word 交付 · HTML 界面原型（界面一律 SVG）。

| 你要的 | 用哪个 |
|---|---|
| 客户能签字、能归档的正式 FS 文档 | `fs-doc-generator`（七阶段全流程） |
| **快速对齐"这个需求怎么做"** | **本 skill** |
| 把定稿 FS 套成客户 Word 模板 | `fs-doc-renderer` |

## 二、多轮迭代模型

| 轮次 | 谁 | 做什么 | 产出 |
|---|---|---|---|
| **R1** | AI 独立完成 | 读需求 → 内部技术勘察 → **出 2 张框架图 + 界面图 + 要点/待确认** | 立刻可看 |
| **R2** | 顾问 | 提意见（"业务理解对不对""这步漏了""不是这么走的"） | AI 改图重出 |
| **R3+** | 双方收敛 | 按需补**界面图**、细化要点 | 迭代同一文件 |

**默认交付到 R1 为止，然后停下来等顾问。** 不要自作主张往下做界面/细节——
那正是被推翻概率最高的部分。

## 三、产出形态（先看这段，决定写哪个文件）

| 顾问给的 | 动作 | 产出 |
|---|---|---|
| **`fs.md`**（或任何 .md 需求文档） | **直接改原文**——保留顾问写的业务内容，把方案章节追加进同一文件 | 原文件（**不新建**） |
| 口述 / 会议纪要 / `.docx` FS / 其他 | 归整后新建 | `30-FS-<需求名>.md`（当前工作目录） |

**为什么 fs.md 直接改**：顾问已经在那份 md 上工作，另起一个文件他就有了两份、要来回对。
**就地改，他打开的还是同一个文件。**

**产出 MD 的结构（R1）**：

```
1 需求理解      3~5 行：交付形态 / 业务目的 / 做与不做（不展开）
2 业务框架图    ★ 泳道图 SVG
3 技术框架图    ★ 分层图 SVG
4 要点与待确认  标准方案结论 + 技术要点 + 待确认项表
5 界面          界面图 N 张（与框架图同批出，见 §6.2）
```

**起手用模板**：照 `references/03-产出模板/30-FS-模板.md` 填，保证每轮结构一致。

**只有一个交付文件**：MD 里内联 SVG，没有 HTML、没有附件——**发给顾问一个文件就够**。

## 四、R1 输入归一与提问闸

**输入处理**：

| 输入 | 怎么读 |
|---|---|
| 口述 / 纪要 / 聊天记录 | 直接归整，不做复述确认 |
| `.md` | 直接读；**产出时改这个文件** |
| `.docx` / `.doc` FS | 走 §4.1「读 docx 的正确姿势」，**不要凭文件名猜内容** |

### 4.1 读 docx 的正确姿势（★ 实测踩过坑，照这个来）

> ⚠️ **可选依赖**：本节依赖 **WorkBuddy 的 `tencent-local-office-edit` skill**（`edsdk.py`，
> editor_sdk 通道）。**这个依赖不是 DSH 自带的**，换台机器 / 换个人很可能没有。
> 没有时按「无该通道」处理：请顾问改给 `.md` / 口述，或自行用 `python-docx`
> 解 `word/document.xml`（docx 本质是 zip）——**不要因为读不了 docx 就凭文件名猜内容**。

走 `tencent-docs-routing` → `tencent-local-office-edit`（editor_sdk MCP）：

```bash
cd "<tencent-local-office-edit skill 目录>"
PY="py -3"           # Windows 官方启动器；macOS/Linux 用 python3。脚本无第三方依赖

"$PY" edsdk.py call open_file file_path="<docx 绝对路径>"      # 返回的 file_id 就是该路径字符串
"$PY" edsdk.py call doc_resolve_document_structure file_id="<路径>" \
      mode=compact text_preview_length=200 limit=0 include_table_cells=true
"$PY" edsdk.py call doc_get_table_info file_id="<路径>" table_id=<表格id>   # ★ 表格完整文本只能靠这个
```

**五个必踩的坑**（前三个是历史教训，4、5 是 2026-09-18 实测补的）：

1. **表格 cell 的 `text_preview` 只有 10 字符，会静默截断**——备注列的内容恰恰是业务逻辑所在，
   **必须用 `doc_get_table_info` 逐表取完整文本**，不截断
2. **`include_table_cells` 只在 `compact` / `outline` 模式生效**——`mode=full` 时表格反而是空的
3. **表格 id 列表不要带 `\r`**：Python 在 Windows 写文件默认把 `\n` 转成 `\r\n`，
   `for tid in $(cat ids.txt)` 取出的 id 会尾带 `\r` → **`doc_get_table_info` 全部失败、
   返回空文件、且无任何报错**（实测 7 张表挂了 6 张）。写法：
   `for tid in $(tr -d '\r' < ids.txt); do ...`，或写文件时用 `newline="\n"`
4. **★ `doc_get_table_info` 的表格正文在 `.block.table.cells`——不是 `.rows`**。
   它是**扁平的 cell 列表**，每个元素带 `row` / `col`（**从 1 起**），
   要自己按 `(row, col)` 拼回二维表。按 `.rows` 解会得到**空表且不报错**（实测踩过）。
5. **★ `edsdk.py` 往控制台按 GBK 打印，重定向捕获必乱码**。
   中文会变成 `����˵����`，`text_preview` 直接不可读。
   **必须在 UTF-8 下调用并落盘**，不要在 PowerShell 里 `>` 抓 stdout：

   ```python
   import os, json, subprocess
   env = dict(os.environ, PYTHONIOENCODING="utf-8")       # ★ 关键
   p = subprocess.run([PY, "edsdk.py", "call", "doc_get_table_info",
                       "file_id=%s" % docx, "table_id=%s" % tid],
                      cwd=SDK_DIR, env=env, capture_output=True)
   data = json.loads(p.stdout.decode("utf-8", errors="replace"))
   ```

**先读 `doc.md` 看工具清单**：该通道**没有"读全文"的单一工具**。
读完后把表格按 `行 | 列` 还原成文本再做勘察——**不要带着截断的备注去画图**。

### 4.2 「1 需求理解」只写四行

① 交付形态（报表 / 批导 / 功能开发 / 增强 / 接口 / 表单，WRICEF 归类）
② 业务目的（一句话）③ 做与不做（**不做的事至少 2 条**）④ 组织与主数据范围（工厂 / 单据类型 / 时间口径）

**不展开**——R1 的篇幅留给两张图。

### 4.3 提问闸（本 skill 唯一会打扰顾问的地方）

**只在两种情况提问，一次 ≤3 题、用选择题弹**：
- 交付形态判不出来（是报表还是要写数据？）
- 范围有硬冲突（同一字段两处规则矛盾）

**不许问**：字段技术名、表名、FM 名、Clean Core 级别、扩展点选哪个——**那是 §5 自己查的**。

其余读不懂的，写进「4 要点与待确认」，标负责人「开发（系统核实）」，**继续往下走**。

## 五、技术勘察（内部动作，不单独成章）

> 前置加载：`references/01-技术勘察/勘察清单.md` + `资料源与降级策略.md`
> ES / ABAP Cloud 场景追加读 `勘察清单-母版.md` 的 `F3+ ES/ABAP Cloud 专项勘察` 组。

**⚠️ 定位与 v2 不同**：勘察**仍然必须做**（不然技术框架图的节点是瞎编的），
但**不再写成一大节文档**——结论只落两处：

1. **技术框架图的节点**（表 / BAPI / 程序 / 逻辑层组件）
2. **「4 要点与待确认」**（标准方案结论 + 2~3 条关键技术要点 + 待确认项表）

### 按需求类型裁剪（不做无用功）

| 需求类型 | 必查 | 预估 L1/L2 查询次数 |
|---|---|---|
| **R 只读报表 / 查询** | 数据落点 · 关联路径 · 存量复用 | 3~5 |
| **W / I / C 批导 / 接口 / 转换** | 标准方案 · 数据落点 · 关联路径 · 扩展点 · 存量复用 | 6~10 |
| **E 增强 / F 表单 / 功能开发** | 全六组（含性能、红线） | 8~14 |

**并行发起**：彼此不依赖的查询**同时发出**，不要一问一答串行等——真连系统时这是最大的单项开销。

### 采源分级与铁律

- **[L1]** 直连系统（ARC-1 MCP）→ **[L2]** 官方检索（sap-docs MCP）→ **[L3]** 内置常识
- **L3 必须进「4 待确认项」**，负责人「开发（系统核实）」；技术框架图的 `lv` 用同一套标注
- **检索用英文**（"销售订单" → sales document）
- **系统未连通不阻塞**：全走 L2+L3 并标注，连通性只影响确信度
- **标准方案必须给结论**（"标准不满足"不合格，要说清标准是什么、差在哪几点）——
  这条最值钱，常能让开发量减少一大截
- **Clean Core 只记录不做约束**（OP 场景 C 级是常态）。自检问句：
  **"如果没有 Clean Core 这个概念，你还会这么选吗？"** 答案是"不会"就别这么选。
  ⛔ ES / ABAP Cloud 场景立场反转：C 级是硬约束，必须走 released API。
- **红线立刻停**：涉及直接改标准对象/标准表 → 停下来报告，不设计绕行方案（见 `02-交付规范/安全红线.md`）。

## 六、出图与交付

### 6.1 两张框架图（R1 必出）★

**语义规则**见 `references/02-交付规范/框架图规范.md`，**生成方式**见 `SVG生成规范.md`。
**一律走脚本**（`biz_swimlane` / `tech_layers`），**不要手写 SVG**——手写坐标必错（实测两张图返工 6 轮）。

- **业务框架图 = 泳道图**：**水平泳道 = 角色，垂直列 = 业务步骤**（最容易画反，务必核对）；
  圆角矩形=人、六边形=系统、文档形=数据；系统浅蓝、成功浅绿、异常浅橙。
  **这张图是给顾问确认"业务理解"的**，所以每个节点用业务语言，不出现表名/程序名
- **技术框架图 = 四层数据流**：触发层 → 逻辑层 → 数据层 → 输出层，
  节点写**真实 SAP 对象名**；**数据层每个节点必填 `lv`**（`[L1]`/`[L2]`/`[L3]`，渲染在右上角）

### 6.2 界面图（与框架图同批出）

**用 SVG，不用 HTML。** 规范与配置见 `references/02-交付规范/SVG生成规范.md`。

**与框架图同批出**——脚本一次生成，不额外耗时；顾问一次就能看到「界面长什么样」。

| 需求形态 | 出几张图 | kind |
|---|---|---|
| 只读报表 / 查询清单 | 1 张（选择屏 + ALV） | `select_alv` |
| 批量导入 / 批量创建单据 | **3 张**（上载 / 结果 / 日志） | `batch_upload` + `batch_result` + `batch_log` |
| 自定义事务码 / 维护界面 | 1 张（Tab + 抬头 + 行项目） | `dynpro` |

> **批导为什么三张**：三张正好对应顾问脑子里的三个问题——
> "我给它什么""它算出什么""错了怎么办"。只画一张，他一定会追问另外两张。

### 6.3 出图与注入命令

**所有图放同一个 `figs.json`，一条命令注入产出 MD**：

```bash
# 选一个你能用的 Python 3（脚本纯标准库、无第三方依赖）：
#   Windows:  py -3        ← 官方启动器，最可靠
#   macOS/Linux: python3
# ⚠️ Windows 上直接写 `python` 可能命中 Microsoft Store 的占位 exe（exit 9009），
#    所以别默认 `python`，先 `py -3 --version` 确认。
PY="py -3"
cd <skill>/scripts
$PY gen_ui_svg.py --demo --json > figs.json              # ① 拿示例配置（7 种图都有填好的例子）
#                                                         ② 改 figs.json
$PY gen_ui_svg.py figs.json --inject "30-FS-<需求名>.md"  # ③ 生成 + 注入，MD 一次成型
```

> **⚠️ `>` 重定向的编码陷阱（必读）**：③ 按 UTF-8 读 `figs.json`，而 `>` 写出来的未必是 UTF-8：
> - **PowerShell `>`**：写成 **UTF-16**（开头 `FF FE`）→ 报 `can't decode byte 0xff`
> - **Windows GBK 控制台 `>`**：写成 **GBK** → 中文图名（`示例-业务框架图`）报 `can't decode byte 0xc0`
>
> 三种可行写法（任选）：
> 1. `PYTHONIOENCODING=utf-8` + **cmd** 重定向：`cmd /c "py -3 gen_ui_svg.py --demo --json > figs.json"`
> 2. 用 **Git Bash / WSL** 的重定向（天然 UTF-8）
> 3. 拿 JSON 后校验一次：`py -3 -c "import json;json.load(open('figs.json',encoding='utf-8'))"`
>
> 好消息：**真实项目里 `figs.json` 是自己手写/编辑的**（不走 `--demo --json` 重定向），
> 所以第 ③ 步 `--inject` 才是每天用的那一步，不受此坑影响。此坑只在第一次取示例配置时踩到。

产出 MD 里图的位置留 `{{SVG:名称}}` 占位（`名称` = JSON 里的 `name`）。
**注入后「未替换占位符」必须是 0。**

**顾问在 R2/R3 提改图意见时**：只改 `figs.json` 对应字段 → 重跑 `--inject` → 完成。

> ★ **重注入前必须先把 MD 里的 SVG 换回占位符**——`--inject` 只替换 `{{SVG:...}}`，
> 对已经内联的 `<svg…>…</svg>` **不会覆盖**（跑了也不报错，图还是旧的，静默失败）。
> 一行搞定（按 `screens` 顺序还原，再注入）：
>
> ```python
> import json, re
> names = [s["name"] for s in json.load(open("figs.json", encoding="utf-8"))["screens"]]
> md = open(MD, encoding="utf-8").read()
> for nm in names:
>     md = re.sub(r"<svg\b.*?</svg>", "{{SVG:%s}}" % nm, md, count=1, flags=re.S)
> open(MD, "w", encoding="utf-8").write(md)
> ```
>
> 还原后**核对占位符个数 == 图个数**，再跑 `--inject`。（实测踩过：不还原直接重跑，
> 页面看着"成功"但图是旧的。）

## 七、硬规则

1. **R1 只出两张框架图 + 要点**，不抢跑界面与细节（抢先做的多半要重做）。
2. **提问闸**：全程 ≤3 题、只用选择题、**只问业务裁决**，技术细节自己查。
3. **fs.md 就地改，不另起文件**；其他输入才新建 `30-FS-<需求名>.md`。
4. **没确认的不编**：图上的字段名/表名必须来自 §5 勘察结论（带来源级别）；
   查不到的写 `【待确认】` + 负责人。
5. **来源级别标注** `[L1]`/`[L2]`/`[L3-待核实]`，L3 必进待确认项。
6. **图只用 SVG，不产出 HTML**；一律走 `gen_ui_svg.py`，**不手排坐标**、不自创色板。
7. **不做 AI 自检**：
   - ❌ 不截图验图、不做 fresh eyes 评审、不逐项打自检清单 —— 直接交给顾问看，**顾问的反馈才是最有效的校验**
   - ✅ 但**脚本的自动检查保留**（零成本）：生成时的**列宽警告**、注入后的**占位符残留计数**
     —— 这两个报错说明"图本身就是坏的/没注进去"，必须处理；除此之外不再人工检查
8. **红线**：不直接写 SAP 标准表、不设计绕行方案、不用 `GENERATE SUBROUTINE POOL` 类通道。
9. **脱敏**：可能对外时按 `02-交付规范/脱敏规范.md` 处理——客户名用代号，
   真实金额/单价/数量/联系人/账号替换为占位符，
   **默认值与测试用例里也不许留具体值**（`{销售组织}` / `{订单类型}` / `{客户}` 这种占位符才安全）。
10. **同一文件的多处修改必须逐条串行 Edit**——严禁一条消息里并发多个 Edit 改同一文件
    （会静默互踩且报成功，母流程实测一次丢 8 处）。

## 八、交付动作（卡片要出，但不自动打开）

调 `present_files` **列出产出文件卡片**——那是用户右键、点开文件与所在文件夹的**唯一入口**，
**不调他就点不到**。同时正文给出**绝对路径** + 简述（标准方案结论 / 出了哪两张图 / 待确认项数）。

- 产出是 `.md`，不会触发内嵌预览，直接列即可。
- **仅当用户当次明确要求**（"打开 / 预览一下"）时才主动打开预览。

## 九、何时退回 fs-doc-generator

| 信号 | 动作 |
|---|---|
| 顾问要的是**能给客户签字**的文档 | 回 `fs-doc-generator` |
| 需求本身**还没说清**（要澄清 5 题以上） | 这不是"快"的场景，回母流程 2A |
| 涉及**金额 / 库存 / 财务过账 / 跨模块 / 接口迁移** | 高风险，建议走母流程补拷打与影响面 |
| 已上线功能的**变更**（怕改坏别的） | 走母流程 1.8 变更通道（有影响面 W1~W5） |

> **一句话判据**：要"快出怎么做"用本 skill；要"经得起签字和审计"回母流程。

## 十、维护说明

- 本 skill 由 `fs-doc-generator` 抽取技术侧内核精简而来；`勘察清单-母版.md` /
  `资料源与降级策略.md` / `安全红线.md` / `脱敏规范.md` 是**母流程的拷贝**，

  ```
  fs-quick-design/
  ├── SKILL.md
  ├── references/

  │   └── 03-产出模板/   30-FS-模板.md（产出 MD 的起手骨架，照抄改）
  ├── scripts/
  │   └── gen_ui_svg.py  图形生成器（7 种 kind = 2 框架图 + 5 界面图，配置驱动 + MD 注入）
  └── examples/          7 张示例图（改脚本后跑 `--demo -o examples` 重出）
  ```
- **改图**：只改 `figs.json` → 重跑 `--inject`。**这是 R2/R3 迭代的常态操作。**
- **改脚本**（色板 / 度量常量）才需要目测一次：用 headless Chromium 截图后 Read 目测：

  ```bash
  CHROME="<你的 chrome / chromium 可执行文件路径>"
  "$CHROME" --headless=new --disable-gpu --hide-scrollbars \
    --window-size=1300,700 --screenshot="out.png" "file:///<生成的.svg>"
  ```
